# alakazam_goal_v1

フーディン v15（ユーザー報告 Rating 880）と v22（同 855）の強みを残し、
同ターンの勝ち筋を「カードごとの点数競争」ではなく、到達できる結果から逆算する
非 ML エージェントです。60 枚のデッキは変更していません。

## 中心となる考え方

1. 公開情報だけで実行可能な同ターン KO 経路を列挙する。
2. `勝利 > 取得サイド > 対象価値 > 必要行動数 > 山札消費` の順で比較する。
3. 選んだ対象を同一ターン中は固定する。ただし勝利や取得サイド増加は再計画を許す。
4. 必要な進化・ドロー・ハンマーを先に行い、ボスの指令を最後に使う。
5. KO 経路がない局面は、v15 の手札・エネルギー管理と v22 の攻撃継続ロジックを使う。

これにより、倒せるベンチの ex がいるのに場の非 ex を倒す問題と、同じ ex の
傷ついたベンチ個体を倒せるのに無傷の場個体へ攻撃する問題を、明示的な結果比較で扱います。

## 主な追加

- 倒せる ex の 2 サイドを、非 ex の 1 サイドより上位にする
- 同ターン中の対象固定と、ボスの指令を最後にする安定した実行順
- オーロンゲ ex を明確な 2 発圏に入れた後の、低サイド対象への早いボスを抑止
- 山札残り 1～2 枚でも、場のノココッチを特性で退かして KO できる場合だけ使用
- ノココッチの逃げエネは、逃げコストを完全に満たし、ベンチのフーディンで
  KO できる場合だけ許可
- 非ミストエネルギーへの改造ハンマーを、即時攻撃阻止または KO 条件成立時に限定
- 旧 ML が担っていた有益な順序を、単サイドのノココッチ進化を先にする明示ルールへ置換

## ファイル

- `main.py`: 非 ML のエントリポイント
- `goal_planner.py`: 結果優先の目標比較と行動順
- `fallback_policy.py`: v15/v22 を基礎にしたカード・盤面ロジック
- `deck.csv`: 変更していない 60 枚デッキ
- `ANALYSIS_GOAL_V1.md`: 設計根拠
- `IMPROVEMENT_COVERAGE.md`: 改善要望との対応表
- `VALIDATION_REPORT_GOAL_V1.md`: 検証結果と限界

Rating 900～1000 は目標であり、teacher-forced 比較だけでは保証できません。
最終評価は新しい実ラダー対戦ログで行います。
