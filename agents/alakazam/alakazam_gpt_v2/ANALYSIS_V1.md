# v1 分析

## 結論

v1では、v33で既に失敗が確認された「木6系統だけのOOF selector」を繰り返さず、盤面をまたいで継続する方策状態を特徴化しました。

結果、完全な時系列分離テストでTop-1 **80.63%**となり、v32提出モデル78.71%を**+1.92ポイント**、v32研究6モデル80.12%を**+0.51ポイント**上回りました。ただし目標90%には届いていません。

## v33から分かったこと

v33はYushin train 35,704判断をepisode単位4-foldでOOF化しましたが、木6モデルのtest oracleは84.62%、selectorは79.18%でした。問題はselectorの学習件数だけでなく、OOF化したbase family自体の多様性不足でした。

そこでv1は、同じ木モデルのseedや容量を増やすことより、上位プレイヤーが直前まで何をしていたかを明示的に入力する方針へ変更しました。

## データ再構成

生ログから次を再構成しました。

- 1,000 JSON episode
- 有効系列999
- MAIN判断49,590
- 意味候補443,714
- 特徴674
- train 35,704判断
- validation 5,038判断
- test 8,848判断

同一カードの別コピーは、option type、card、attack、target、target HP、energy、in-play area等の9要素で統合し、従来の「意味的一致」と同じ定義で評価しました。

## 追加した方策状態

- 直前4判断のaction type / card / attack / target
- ability、attack、bench、Boss、energy、evolve等の累積回数
- episode内の判断番号
- 同一ターン内の判断番号
- 最後のattack / energy / evolve / trainerからの経過ターン

これらは現在・過去の公開観測と、過去に自分が実際に選んだ行動だけから作られます。未来の行動、勝敗、相手非公開手札は入力していません。

## モデル比較

| モデル | Validation Top-1 | Test Top-1 | 判断 |
|---|---:|---:|---|
| 255葉 sequence-state LambdaRank | **80.81%** | 80.63% | 提出採用 |
| 127葉 | 80.57% | 80.67% | validationで劣後 |
| 63葉 | 78.66% | 79.28% | 不採用 |
| OOF residual selector | 80.94% | **81.09%** | 改善が小さく不安定、研究用 |
| leak-free GRU top-2 selector | **81.38%** | 81.01% | PyTorch依存、研究用 |

GRUの初回実験では現在の正解候補IDが入力へ混入し、検証92%台という不正な数値が出ました。このリークは検出後に破棄し、現在の正解情報を除外して再学習しました。v1の報告値には使用していません。

## 誤り構造

v1単木のtestは、Top-1 80.63%に対してTop-2 93.30%、Top-3 96.99%です。正解は多くの場合上位2候補に入っています。

主な弱点は、Trainer、Energy、Boss、Xerosic、Retreatのような、同じ盤面でも長期計画や対面方針によって順序が変わる判断です。進化・攻撃・特性は比較的高精度でした。

## 次の研究方針

90%へ進むには、次の優先順位が妥当です。

1. 新しい上位ログを完全未閲覧holdoutとして確保する
2. 上位2候補のpairwise selectorを、より多くの教師・対面・方策状態で学習する
3. Boss / Xerosic / Energy / Retreatを、それぞれ専用の階層ヘッドで再順位付けする
4. foldごとのDeepSets / AttentionをOOF化し、木以外の正解集合をselectorへ渡す
5. 実戦ではv31をchampionとし、v1は安全性・レート・対面別指標をA/Bする

既知testを何度も見ながら90%へ合わせることは最終目標の達成とはみなしません。最終判定は新規の完全未閲覧holdoutで行う必要があります。
