# v4 分析

## 結論

v4では、追加された上位3チームのフーディンログを教師候補として再構成し、既存Yushin時系列testを固定したまま、教師追加・追学習・consensus memory・teacher expert ensembleを比較した。

最終的に採用したのは、v3のYushin rich type modelを85%、Rmyログだけで学習したtype expertを15%混ぜる構成である。時系列test Top-1は81.78%（7,236 / 8,848）となり、v3の81.62%（7,222 / 8,848）から14判断、+0.16ポイント改善した。

目標90%は未達である。改善はvalidationとtestの双方で再現したが、差は小さく、v31を実戦championとして維持し、v4は新しいchallengerとして扱う。

## 追加データ監査

追加ZIPをv1以降と同じMAIN判断、意味候補9要素、674候補特徴へ変換した。

| Rmy submission 54750312 | 699 | 29,871 | 262,001 |

既存主教師はYushin Ito 999episode、49,590判断、443,714意味候補である。追加分を含む教師候補全体は2,873episode、142,640判断、1,266,599意味候補となった。

## 教師間の差

v3のtype modelを追加ログへそのまま適用した行動種一致率は次だった。

- 新Yushin: 84.14%
- Majkel: 71.38%
- Rmy: 68.79%

同じフーディン構築でも、進化、ベンチ展開、Trainer、Energy、攻撃の順序には大きな教師差がある。全教師を同じ正解として単純に混ぜると、主教師Yushinの完全一致精度を下げる可能性が高い。

## 検証した方法

### 1. 直接追学習

追加YushinまたはMajkelを低重みでv3へ追学習した。validationの最大値はv3を超えず、古いsubmissionや別教師の手順を全面的に学ぶ方法は不採用とした。

### 2. Multi-teacher consensus memory

量子化した方策状態について、複数観測で同じ行動種が支持された場合だけ上書きした。validationでは4,116から4,118一致へ増えたが、固定条件をtestへ適用すると7,222から7,212へ悪化したため棄却した。

### 3. 独立teacher expert

各追加教師だけで行動種expertを学習し、v3確率とのblendをvalidationで比較した。

- Yushin expert validation行動種精度: 83.49%
- Majkel expert: 69.59%
- Rmy expert: 72.75%

Rmy expert単体は主教師模倣器として弱い。しかし、v3へ15%だけ混ぜると、v3が誤りやすいTrainer・Attack・Bench・Energy間の境界を一部補正した。

## 最終構成

- v3 rich type primary model: 85%
- Rmy type expert: 15%
- action-type gate confidence: 0.45
- 同一行動種内候補: v1 LambdaRank
- v31～v3の安全ゲート、teacher memory、v29 fallback、リーサル保護を維持
- デッキ60枚は変更なし

Rmy expertは356入力特徴、11クラス、151 boosting round、1,661本のcompact treeである。runtimeはXGBoostへ依存せず、純Pythonで両モデルを推論して確率をblendする。

## 最終結果

| 指標 | v3 | v4 |
|---|---:|---:|
| Validation Top-1 | 81.70%（4,116 / 5,038） | **81.94%（4,128 / 5,038）** |
| Test行動種精度 | 84.86% | **84.96%** |
| Test Top-1 | 81.62%（7,222 / 8,848） | **81.78%（7,236 / 8,848）** |
| Test改善 | — | **+14判断、+0.16pt** |
| 目標 | 90% | 未達 |

v4とv3で最終選択が変わった行動種判断は89件だった。そのうちv4が新たに正解したものが43件、v3から誤りへ変わったものが29件で、純増14件である。

## 判断

追加ログには情報価値があったが、教師を増やすだけで90%へ到達する結果ではなかった。v4はv3より一貫して改善したためchallengerとして採用する。ただし改善幅は小さく、Kaggle Ratingの上昇を保証しない。

90%へ進むには、別教師の単手選択を混ぜるより、同一教師の「攻撃またはターン終了までの行動列」を教師とする模倣プランナー、あるいは合法手適用後の盤面遷移を評価するモデルが必要である。
