# v29 analysis

## 1. Problem definition

v28の実レートは約800で、上位ログの行動を十分に再現できていませんでした。そこで「同じ局面で上位エージェントが選んだ意味的に同じ手を選べるか」を直接の学習・評価対象にしました。

候補indexの完全一致だけでは、同名カードの複数コピーを誤答として数えてしまいます。v29ではカードIDまたは技IDに加え、対象のカードID・HP・エネルギー・場の位置が同じ候補をsemantic同値と定義しています。

## 2. v28の診断

上位5チーム、30,359 decisionをv28で再生した結果は次の通りです。

| 指標 | v28 |
|---|---:|
| exact一致 | 54.69% |
| semantic一致 | 59.57% |
| intent一致 | 60.21% |
| MAIN semantic一致 | 41.12% |

入れ子選択の一部は高一致でしたが、各ターンの大枠を決めるMAIN選択が最大のボトルネックでした。旧ランカー単体の反実仮想評価でも、MAIN top-1は55.37%、top-3は81.01%に留まりました。

v28自身の55試合も調べました。敗戦時の攻撃時手札は平均8.81枚で、勝利時の13.61枚より大幅に少なく、単独ポケモンでターンを終えた試合は9試合中6敗でした。個別のBoss対象だけでなく、エンジンの回し方、盤面維持、展開順序をまとめて学ぶ必要があると判断しました。

## 3. Teacher corpus

凍結済み上位ログから、同一デッキハッシュ `cc38cb450b86770a` の順位2、3、5、6、8を採用しました。

- 361試合
- MAIN 18,336 decision
- 合法手192,179候補
- episode hash単位でtrain 70%、validation 10%、test 20%
- 順位重み `1 / sqrt(rank)`
- 勝敗は小さな補助重みだけに使用

盤面の近い候補がtrainとtestへ漏れないよう、候補行ではなく試合単位で分割しています。

## 4. Model design

LightGBM LambdaRankを使用し、同一decision内の合法手を直接順位付けします。主な特徴量は次の通りです。

- ターン、手札、山札、サイド、エネルギー、HP、状態異常
- 自分・相手のベンチ5枠を順序付きで表したカード、HP、ダメージ、エネルギー
- フーディン進化ルート、攻撃準備、ノココッチエンジン、山札runway
- 各合法手のカード、技、対象、使用後手札、推定打点、KO維持
- 同時に提示された行動種・カード種と候補数
- v28の選択、v28の生スコア・gap・rank
- 旧LightGBMランカーのスコア・gap・rank

これはv28を捨てるモデルではなく、v28の判断を残差特徴として使い、上位ログが示す差分を学ぶモデルです。validationで278 treeを選び、held-out評価後に凍結コーパス全体で最終artifactを再学習しました。

## 5. Generalization result

未見episode 2,463 decisionでのsemantic recallです。

| 指標 | v29 | v28 fallback |
|---|---:|---:|
| top-1 | 66.30% | 48.72% |
| top-2 | 83.56% | - |
| top-3 | 90.95% | - |
| v28またはv29のoracle top-1 | 74.18% | - |

行動別top-1は、進化83.03%、特性82.39%、逃げる74.19%、攻撃73.35%、ベンチ72.92%でした。一方、サポート44.94%、Boss 31.37%、エネルギー55.37%は今後の改善余地です。

ユーザー目標の「9割以上で上位の選択肢」は、未見盤面のtop-1では未達です。top-3には90.95%で含まれますが、それをtop-1精度と表現してはいけません。

## 6. Runtime policy

モデルはsingle-select MAIN contextだけに適用します。閾値0.20未満、入れ子・複数選択、残り時間2秒未満、モデルエラー時はv28へ戻します。

さらに以下をhard guardにしました。

- v28が即時勝利攻撃を持つ場合は必ず維持
- v28のBoss確定ルートを非Bossで上書きしない
- 現在成立しているKOを壊す候補を拒否
- Activeフーディンが攻撃可能なときENDを拒否
- 盤面2体以下でノココッチを山札へ戻す特性を拒否
- 最終的な合法性を再検査

安全制約を増やしすぎると教師模倣が悪化しました。山札薄時の追加draw guardは実ラダーの裏付けがないため採用していません。

## 7. Frozen-corpus regression

最終runtimeを上位5チームの全30,359 decisionへ再適用した結果です。

| 指標 | v28 | v29 |
|---|---:|---:|
| exact一致 | 54.69% | 79.59% |
| semantic一致 | 59.57% | 84.82% |
| MAIN semantic一致 | 41.12% | 82.29% |

これは学習に使ったepisodeを含む回帰試験です。モデルがruntimeへ正しく組み込まれた証拠にはなりますが、未見盤面の期待値にはheld-out 66.30%を使います。

## 8. Remaining work

次の改善対象は明確です。

1. Boss、サポート、エネルギー選択用の局面別expertを追加する。
2. context 8のdiscardなど、一致率が低い入れ子選択を別モデル化する。
3. 最新上位ログを時系列holdoutにし、同一snapshot内の近似局面依存を減らす。
4. v29を実提出し、負けmatchupを再取得して教師との分布差を測る。

現段階のv29は、v28より上位方策へ大きく近づいた検証済み候補ですが、「最強」は実レートでまだ証明されていません。
