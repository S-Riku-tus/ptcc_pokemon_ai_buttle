# v30 分析

## 結論

v29の問題は、教師ログが361試合と少ないことだけではありませんでした。盤面を十分に区別できない特徴、上位教師の行動を全contextで再現する経路の欠如、v29自身の選択からどの候補へ修正すべきかを学ぶ残差設計の不足が重なっていました。

v30では、同一デッキの上位ログを2,361試合へ拡張し、既知盤面は損失なく再現し、未見盤面はv29からの修正量を学ぶ二層構造にしました。

## 1. 教師ログ監査

対象はデッキハッシュ `cc38cb450b86770a` のみです。

| コホート | 試合数 |
|---|---:|
| 現在の上位5チーム | 361 |
| Majkel1337 full archive | 1,000 |
| Yushin Ito full archive | 1,000 |
| 合計 | 2,361 |

全contextで200,798選択、MAINは123,656選択でした。このうち、単一選択で合法手が2個以上ある121,708盤面を学習に使いました。

完全な観測キーは199,558個で、同一キーに異なる意味的正解が付く衝突は0件でした。一方、時系列holdoutに対するキー再利用率は約1.66%しかありません。したがって、ログの丸暗記だけでは未見対戦の大半を処理できません。

## 2. v30の構造

### 既知盤面の教師メモリ

step番号と残り時間だけを除いた観測、合法手集合、プレイヤー視点をキーにします。教師の配列indexを保存するのではなく、カード・技・対象を含む意味的行動を保存するため、同じカードの別個体でindexが変わっても同じ手を選べます。

### 未見盤面の残差ranker

v29が各候補へ付けた生スコア、v29選択との一致、順位とスコア差を入力へ追加し、「一から方策を作る」のではなく「v29のどこを教師に合わせて直すか」を学習しました。

主な追加情報:

- 直近の公開行動履歴と現在ターンの行動系列
- ActiveとBench各枠の進化元、エネルギー、どうぐ
- search中の公開deck候補
- 選択肢集合全体のカード・行動種別
- v29の候補別スコア、順位、選択

学習は各コホート内で時系列70/10/20に分割しました。順位上位、現在の上位環境、勝利試合へ緩やかな重みを付けています。

### 安全ゲート

学習器の選択であっても、即時リーサル、現在のKO、完成したBossルート、攻撃可能なフーディン、最低限の盤面枚数を壊す場合は採用しません。対象外contextと例外は凍結したv29へ戻します。

## 4. 既知ログ再現

保存済み教師ログ100試合、11,610選択を実際のv30ランタイムへ再入力しました。

- 意味的一致: 100%
- 配列index完全一致: 97.96%
- エラー: 0

index差は同一カードの別個体や順序差であり、意味的行動は一致しています。この結果と未見73.95%は別の指標です。

## 5. 次に90%へ近づける条件

現状のボトルネックはモデル容量より、観測だけでは区別できない教師意図と、長期プランを直接教師化していない点です。次版では、行動一致だけでなく「その後数手の到達状態」をラベル化し、教師チーム・対面・ゲーム段階ごとのmixture-of-experts、Boss/retreat/energy専用head、複数教師が同意する盤面だけの高確度ラベルを導入するのが有力です。

v30は、既知問題100%と未見top-3 95%を達成しましたが、未見top-1 90%を達成したものとしては扱いません。
