# v34 分析

## 出発点

v33は実ラダー最終レート916.9（submission 55129390、public 42-29）でフーディン系列の最高値を出し、championになりました。v31の881.2、v32の871.9を上回っています。

v33はその時点で「何が律速か」を4つの測定で切り分けていました。特徴表現は原因ではない（1判断内でビット単位に同一な候補行は0件、理論上限100%）、容量不足でもない（学習Top-1 96.9%対ホールドアウト78.1%）、記憶や近傍法の余地もない（学習35,704判断の盤面キーはすべて一意）、そして誤りの約60%はターン内の実行順のずれである、という4点です。結論は「汎化が律速（variance limited）」でした。

v34はこの診断の続きから始めています。まず「variance limited」が具体的に何の分散なのかを確定し、次にそれが指し示すレバーを引きました。

## 測定1: どの分散が効いているのか

「分散が律速」には2つの意味があります。**学習の当てはめが不安定**（seedを変えると別のモデルになる）なのか、**データ標本が足りない**（別のデータを引けば別のモデルになる）なのかです。処方箋は正反対で、前者はアンサンブル、後者はデータ追加です。

v33の設定（large_leaf、ターン順序gradedラベル、v33のコーパスと凍結ホールドアウト）のまま、seedだけを6通り変えて測りました。

| seed | best_iteration | validation Top-1 | test Top-1 |
|---|---:|---:|---:|
| 1091（v33が採用） | 1005 | 78.98% | 79.51% |
| 7 | 746 | 78.48% | 79.16% |
| 42 | 1048 | 78.88% | 79.61% |
| 2024 | 801 | 78.80% | 79.33% |
| 31337 | 644 | 78.05% | 78.80% |
| 65535 | 921 | 78.80% | 79.34% |

testの幅は0.81ポイント、標準偏差は0.26ポイントです。候補集合内でz標準化して平均するアンサンブル（ランタイムが実際に使う合成方式）を1個から6個まで積み上げた結果は次のとおりです。

| 合成数 | validation Top-1 | test Top-1 |
|---|---:|---:|
| 1 | 78.98% | 79.51% |
| 2 | 78.60% | 79.44% |
| 4 | 78.94% | 79.52% |
| 6 | 78.74% | 79.37% |

**seed平均化は効きません。** 6個平均のtest 79.37%は、6個の単純平均79.29%をわずかに上回るだけで、最良seedの79.61%には届きません。validationでも1個が最高です。

一方で「6個のうち少なくとも1個が正解する」割合（seed oracle）は84.22%あります。つまり誤りの多くは、モデルが自信を持って間違えているのではなく、スコア差がほぼ無い候補の間で毎回コインを投げ直しているような判断です。平均を取ってもコインの偏りは変わりません。

**結論: 律速は当てはめの不安定性ではなく、データ標本です。** アンサンブルは無効、データ追加が唯一のレバーです。この時点でv34の方針が決まりました。

同時に誤りの内訳も更新しました。seed 1091の誤り1,813件のうち1,132件（62.4%）は教師も同じターン内で打つ手の順序ずれ、1,558件（86.0%）はモデルのTop-3内に教師の手が入っています。候補集合の絞り込みはできていて、順位付けだけが外れている構図です。

## 測定2: 教師ログは増やせた

v33は「同一提出のログを1桁多く集める」ことを未達目標への3つの道の1つに挙げ、手元の1,288試合に対して90%到達には約16,400試合必要と外挿していました。

教師提出54773249は2026-08-01時点でもラダー上で稼働しており、Kaggle EpisodeServiceに1,000試合が残っていました。うち980試合はv33のコーパス（最大episode ID 88172479）より新しい未取得分です。全件取得し、980件すべてについてリプレイの`TeamNames`が指定シートでYushin Itoであることを個別に検証しました（不一致0、欠損0）。

コーパスは1,288試合から**2,268試合**（67,340判断→115,169判断、候補行587,113→1,018,082）になりました。

### ホールドアウトを組み直した

追加分はすべてv33の凍結ホールドアウト（validation ≥ 88002730、test ≥ 88050020）より新しいエピソードです。したがってv33のホールドアウトはv34には使えません。使えば「テスト期間より後の試合で学習する」ことになります。

v34はエピソードIDで時系列に切り直しました。最新200試合をtest（9,977判断）、その1つ前の100試合をvalidation（4,331判断）、残る1,968試合をtrainとしています。境界はvalidation ≥ 88885178、test ≥ 89039056です。

比較の土俵を揃えるため、**v33が実際に学習できたエピソード集合（自身の凍結境界より古い984試合）だけで同じ設定を再学習し、この新しいホールドアウトで採点しました**。これがv34の基準線です。

## 測定3: 切り捨てに見えたものは早期打ち切りのノイズだった

最初のアブレーションは「最新何%の学習エピソードを使うか」を振るものでした。結果は次のとおりで、単調ではありません。

| 学習割合 | 試合数 | best_iteration | validation | test |
|---|---:|---:|---:|---:|
| 最古984（v33基準線） | 984 | 515 | 79.01% | 77.22% |
| 最新25% | 491 | 690 | 79.17% | 76.30% |
| 最新50% | 982 | 908 | 81.21% | 78.79% |
| 最新62.5% | 1228 | 470 | 80.70% | 77.81% |
| 最新70% | 1375 | 888 | 81.51% | 79.47% |
| 最新75% | 1473 | 920 | 82.24% | 80.63% |
| 最新80% | 1571 | 589 | 81.53% | 78.74% |
| 最新87.5% | 1718 | 962 | 82.27% | 81.19% |
| 全部 | 1964 | 656 | 81.46% | 79.22% |

「最新75%が全データを上回る」と読めますが、順位は**best_iterationにほぼ完全に連動**しています。早期打ち切りが700本未満で止まった実行はすべて低く、880本以上まで回った実行はすべて高い。12回の実行を通じた相関はvalidationで0.56、testで0.65でした。

原因は打ち切り基準の不整合です。v33のパイプラインはLightGBMの`ndcg`（gradedラベル上）で打ち切りを決めていますが、報告し実際に配備する指標は厳密Top-1です。この2つは別の目的関数で、最大点が違います。しかも打ち切り点は毎回引き直されるので、コーパス比較の差がそのまま打ち切りのばらつきに埋もれます。

そこで**打ち切りを外し、固定本数まで学習した1本のブースタを、木の接頭辞ごとに採点し直しました**。1回の学習から本数と精度の曲線全体が観測できます。

| 本数 | 最新75% val / test | 最新87.5% val / test | 全部 val / test |
|---:|---|---|---|
| 600 | 81.09 / 78.57 | 81.34 / 79.01 | 81.11 / 79.09 |
| 1000 | 81.97 / 80.76 | 82.18 / 81.26 | 82.15 / 80.08 |
| 1600 | 82.43 / 81.55 | 82.78 / 82.82 | 82.57 / 80.72 |
| 2000 | 82.27 / 82.73 | 82.96 / 82.98 | 82.84 / 80.95 |
| 2200 | 82.50 / 82.73 | 82.96 / 82.96 | 82.98 / 82.06 |

終盤6点の平均は、最新75%が val 82.36% / test 82.36%、最新87.5%が val 82.84% / test 82.91%、全部が val 82.79% / test 81.11% です。

**本数を揃えると切り捨ての差はほぼ消えました。** 最初の「最新75%が最良」は早期打ち切りのノイズでした。同時に、どの曲線も1,600〜2,200本まで上昇を続けており、**v33が配備した1,005本は大幅な学習不足**だったことが分かります。これが今回の最大の発見です。

最新87.5%だけはvalidationとtestが0.07ポイント差で一致し（82.84% / 82.91%）、全データは曲線全体を通じてvalidationがtestを1.7ポイント上回り続けます。validationで選ぶと87.5%と全データはほぼ同点（82.84%対82.79%）ですが、2つの独立したホールドアウトで一致する前者を採りました。

## 測定4: v33のラベルと重みは、公平に測り直しても正しかった

早期打ち切りで得た結論はすべて信用できなくなったので、ラベル設計と recency 重みを、最新87.5%・2,200本固定で測り直しました。

| 設計 | validation | test |
|---|---:|---:|
| ターン順序graded + recency(floor 0.25, power 2.0) | **82.96%** | 82.96% |
| 二値ラベル + 同じrecency | 82.84% | 83.10% |
| ターン順序graded + recency無し（一様） | 82.61% | 82.83% |

validationはv33の設計を支持します。ただし graded と二値の差は0.12ポイントで、**v33でのgradedの優位（同一ホールドアウトで+1.99ポイント）はコーパスが倍増し本数が適正化されると実質的に消えます**。順序情報は、データが少ないときに構造を補う役割だったと解釈しています。継続性のためgradedを維持しましたが、差は測定誤差の範囲です。

recencyを一様にすると0.35ポイント下がるので、こちらは維持する意味があります。

## v34の構成

変えたのは2つだけです。

1. **コーパス**: 同一提出を再取得して2,268試合にし、最新87.5%（学習1,718試合）を使う
2. **木の本数**: NDCG早期打ち切りをやめ、validationのTop-1で直接選ぶ（選ばれた本数は2,050）

v31から続く安全ロジック（リーサル保護、KO破壊の拒否、Alakazamが攻撃できる間はターンを終えない、盤面2体以下でDudunsparceを戻さない、非対応・低残時間・違法時のv29フォールバック）、Majkel盤面メモリ、デッキ60枚、657特徴、large_leaf設定、seed 1091、ラベル、recency重みはすべてv33のままです。

## ラダー側の診断: 何が勝敗を決めているか

オフラインのTop-1は強さの尺度としては弱い代理指標です。v33はTop-1が+0.80しか動いていないのにレートが+35.7動きました。そこで実ラダーのリプレイから、行動そのものを数えました。

v31（69試合）、v32（65試合）、v33（72試合）の全リプレイから、自分のシートの進化と攻撃を数えた結果です。

| 版 | 勝率 | Powerful Hand/試合 | 4回以上の試合比率 | Dudunsparce/試合 |
|---|---:|---:|---:|---:|
| v31 | 50.7% | 3.75 | 52.2% | 2.22 |
| v32 | 56.9% | 3.78 | 53.8% | 2.82 |
| v33 | 58.3% | **4.15** | **58.3%** | 2.46 |

**Powerful Handの回数が唯一の決定要因として残っています。** v33の72試合を回数で分けると、0〜3回の試合は8勝30敗（27%）、4回以上は34勝42敗中の34勝（81%）です。54ポイントの差があり、他のどの指標もこれほど分離しません。

一方、過去に問題として記録していたDudunsparce（Run Away Draw）の使用不足は**解消しています**。以前は「0回の試合は0勝」でしたが、v33では0回でも6勝11敗（55%）で、使用回数のバケット間で勝率がほぼ平坦（55% / 67% / 69% / 50%）です。場の水準2.86に対して2.46まで来ており、このレバーは引き切ったと判断しました。

つまり現時点で狙うべきは「4回以上Powerful Handを打てる試合の比率」で、それはAlakazamを盤面に出し続けられるかで決まります。v34のevolveクラスが+11.91ポイントであることは、この観点と整合します。

**ただしこれは整合であって因果の証明ではありません。** オフラインの一致率が上がったことが実ラダーのPowerful Hand回数を増やすかは、投入して測るまで分かりません。

## 90%目標について

到達していません。83.01%が現時点の最高です。

ただしv33が示した外挿は大きく外れました。v33は「1桁あたり+8.47ポイント」で90%には約16,400試合必要としていましたが、実際には試合数を1,288→2,268（0.245桁）にし、本数の選び方を直しただけで+5.79ポイント動いています。外挿が過小評価だった理由は、v33の測定自体が早期打ち切りのノイズに乗った点にあります。伸びしろの大半はデータではなく**学習不足**でした。

順序を問わない一致率（turn-set）は95.15%で、90%を超えています。要求指標は厳密Top-1なので達成判定には使っていません。

## 不採用にしたもの

- **seedアンサンブル**: 6seed平均でtest 79.37%、最良seed79.61%を下回る。推論コストがseed数に比例して増える一方で利得が無い
- **全データ学習**: validationでは最新87.5%とほぼ同点だが、testが1.7ポイント下振れし続ける
- **二値ラベル**: validationで0.12ポイント下。ただし差は測定誤差の範囲で、gradedの優位はもう主張できない
- **recency一様化**: validationで0.35ポイント下

## v35に向けて残っている観測

- **boss（Boss's Orders）の一致率が47.94%と突出して低い**。n=194と小さいですが、ベンチのポケモンを引きずり出す札は盤面を大きく動かすので、専用の扱いを検討する価値があります
- **trainerクラスが70.48%（n=1843）で最大の絶対損失源**です
- 誤りの86%は教師の手がTop-3内にあります。上位3候補に絞ってから決める2段構成は未検証です
- 教師提出54773249はまだ稼働中なので、ログはさらに増えます。ただしAPIが返すのは直近1,000件なので、定期取得しないと取りこぼします
