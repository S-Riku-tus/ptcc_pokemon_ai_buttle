# v34 変更点

## モデル

- 教師提出54773249をKaggle EpisodeServiceから再取得し、未取得だった980試合を回収（コーパス1,288→2,268試合、67,340→115,169判断、候補行587,113→1,018,082）
- 追加980件すべてについて、リプレイの`TeamNames`が指定シートでYushin Itoであることを個別に検証（不一致0・欠損0）
- 追加分はv33の凍結ホールドアウトより新しいため、ホールドアウトをエピソードIDで時系列に切り直し（validation ≥ 88885178の100試合、test ≥ 89039056の200試合、train 1,968試合）
- v33が実際に学習できたエピソード集合（最古984試合）を新ホールドアウトで再学習し、直接比較できる基準線を作成
- 学習コーパスを最新87.5%（1,718試合）に限定
- **木の本数の選び方をLightGBMのNDCG早期打ち切りからvalidationのTop-1直接選択へ変更**。配備本数は1,005→2,050
- 配備モデルは全2,264有効エピソードの最新87.5%（1,981試合・97,511判断）で再学習

## 検証・測定

- seed分散を6通りで測定し、seedアンサンブルが無効であることを確認（6個平均test 79.37%対最良seed 79.61%、seed oracle 84.22%）
- 早期打ち切りとコーパスの交絡を、打ち切り無し・固定本数・木の接頭辞ごとの採点で切り分け
- ラベル設計とrecency重みを本数固定条件で測り直し、v33の選択が正しいことを再確認（gradedの優位は+1.99→+0.12ポイントに縮小）
- v31/v32/v33の全ラダーリプレイからPowerful HandとDudunsparceの使用回数を集計し、勝敗要因を再特定
- v34回帰テストを追加（配備本数、コーパス来歴、単一メンバー配備、v31安全シェルの保持）
- エクスポート時に、メタデータが`compact_booster`の木リストを上書きしないことを検証するガードを追加

## 変更していないもの

デッキ60枚、657特徴、large_leaf設定（num_leaves 127、learning_rate 0.03、min_child_samples 40、colsample 0.88）、seed 1091、ターン順序gradedラベル、recency重み（floor 0.25・power 2.0）、v29フォールバック、Majkel盤面メモリ、v31から続く安全ガード5種、ランタイムの判断ロジック。

環境変数は`ALAKAZAM_ML_V34_*`を追加し、v33・v32・v31名を後方互換として受け付けます。

## 結果

新しい時系列ホールドアウト（test 200試合・9,977判断）の厳密Top-1は、v33基準線の77.22%から**83.01%**へ（+5.79ポイント）。validationは79.01%から83.12%へ。Top-3は98.48%、順序非依存のturn-setは95.15%です。

目標90%は未達です。
