# alakazam_ml_v34

v34はv33（実ラダー916.9、フーディン系列champion）を基盤にした挑戦版です。デッキ60枚、v29安全フォールバック、Majkel盤面メモリ、リーサル保護などの安全ロジックはv31から一切変更していません。変えたのは、未知のMAIN盤面で「上位チームと同じ手を選ぶ」順位モデルの**学習データ**と**木の本数の決め方**の2点だけです。

**実ラダー未投入です。** 以下はすべてオフラインの測定値です。

## v34で何が変わったか

**同一教師のログを再取得して倍近くにした。** 教師提出54773249は2026-08-01時点でもラダーで稼働しており、Kaggle EpisodeServiceに1,000試合が残っていました。うち980試合はv33のコーパスより新しい未取得分です。980件すべてリプレイの`TeamNames`でシートを検証したうえで取り込み、1,288試合→**2,268試合**（115,169判断）になりました。

**木の本数をvalidationのTop-1で直接選ぶようにした。** v33のパイプラインはLightGBMの`ndcg`で早期打ち切りしていましたが、報告し配備する指標は厳密Top-1です。目的関数が違うため打ち切り点が毎回ずれ、コーパス比較の差がそのノイズに埋もれていました。打ち切りを外して固定本数まで学習し、木の接頭辞ごとに採点し直すと、精度は1,600〜2,200本まで上昇し続けます。**v33が配備した1,005本は大幅な学習不足でした。** v34は2,050本を配備します。

**学習コーパスは最新87.5%に限定した。** 本数を揃えると切り捨ての効果はほぼ消えますが、最新87.5%だけはvalidationとtestが0.07ポイント差で一致し（82.84% / 82.91%）、全データはvalidationがtestを1.7ポイント上回り続けます。

## 結果

追加分がv33の凍結ホールドアウトより新しいため、ホールドアウトはエピソードIDで時系列に切り直しています（最新200試合をtest、その前の100試合をvalidation）。比較のため、**v33が実際に学習できたエピソード集合だけで同じ設定を再学習し、同じホールドアウトで採点した基準線**を置いています。

| 指標 | v33基準線 | v34 | 差 |
|---|---:|---:|---:|
| validation Top-1 | 79.01% | **83.12%** | +4.11 |
| **test Top-1** | **77.22%** | **83.01%** | **+5.79** |
| test Top-2 | — | 95.33% | — |
| test Top-3 | — | 98.48% | — |
| test turn-set（順序非依存） | — | 95.15% | — |

**要求された90%には届いていません。** 83.01%が現時点の最高です。

行動クラス別では、最大クラスのevolve（Dunsparce→Dudunsparce、Abra→Kadabra→Alakazam）が82.36%→**94.26%**（+11.91ポイント）と最も伸びました。hammer（n=123）以外の全クラスで改善しています。

## 測定して却下したもの

**seedアンサンブルは効きません。** v33は「variance limited」と診断していましたが、それが当てはめの不安定性なのかデータ標本の不足なのかは未確定でした。seedを6通り振ると、6個平均のtest 79.37%は最良seedの79.61%に届きません（seed oracleは84.22%）。誤りの多くはスコア差がほぼ無い候補間のコイン投げで、平均しても偏りは変わりません。**データ追加が唯一のレバー**であることが確定し、これがv34の方針を決めました。

**v33のラベル設計とrecency重みは、本数固定条件で測り直しても正しい選択でした。** ただしターン順序gradedの優位は、v33の同一ホールドアウトでの+1.99ポイントから+0.12ポイントに縮小しています。コーパスが倍増し本数が適正化されると、順序情報の寄与は実質的に消えます。

**全データ学習**（validationでほぼ同点だがtestが1.7ポイント下振れ）、**二値ラベル**（-0.12）、**recency一様化**（-0.35）も却下しました。

## ラダー側で見えていること

オフラインのTop-1は強さの尺度としては弱い代理指標です（v33はTop-1 +0.80でレート+35.7）。そこで実リプレイから行動そのものを数えました。

| 版 | 勝率 | Powerful Hand/試合 | 4回以上の比率 |
|---|---:|---:|---:|
| v31 | 50.7% | 3.75 | 52.2% |
| v32 | 56.9% | 3.78 | 53.8% |
| v33 | 58.3% | **4.15** | **58.3%** |

v33の72試合では、Powerful Hand 0〜3回で8勝30敗（27%）、4回以上で34勝8敗（81%）。54ポイントの差で、他のどの指標もこれほど分離しません。以前に問題視していたDudunsparce使用不足は解消済みで、使用回数と勝率の相関は消えています。

v34のevolveクラスの伸びはこの観点と整合しますが、**整合であって因果の証明ではありません。** 実ラダーでPowerful Hand回数が増えるかは投入して測る必要があります。

## 検証

188テスト成功、静的検証成功、デッキ変更なし。

推論はv33の92.2 msから135.0 ms（+46.4%、p95 264.2 ms、max 374.2 ms）。木が2倍でも線形には増えません（特徴構築が共通のため）。モデル選択率0.8166・フォールバック率0.1834はv33と完全に一致し、安全挙動は不変です。v33は実ラダー72戦・両シート142件すべて`DONE`、エラー0・タイムアウト0を92.3 msで達成しているので、135 msでも余裕はあると見ていますが、実測はまだありません。

ローカル対戦40戦ずつでv33に19-21、v31に23-16-1、いずれもクラッシュ0・違法手0です。**この試合数では強弱を分離できません**（v33自身もv32に19-21でありながらラダーでは+45でした）。安全性の確認としてだけ扱ってください。

## 次に投入するときの見方

v33の916.9との比較は、1ランでは決着しません。過去に同等エージェントの2ラン間で38.8ポイントの振れが観測されています。判断は生のレートではなく、相手の`initialScore`で条件付けた勝率と、`scripts/analyze_alakazam_v34_behaviour.py`が出すPowerful Hand 4回以上の比率で行ってください。

詳細は`ANALYSIS_V34.md`と`VALIDATION_REPORT_V34.md`を参照してください。v33をchampion、v34をchallengerとして保存します。
