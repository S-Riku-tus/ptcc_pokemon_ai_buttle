# alakazam_ml_v35

v35 は v34 の**ランタイムだけ**を変えた版です。モデル（`ranker_model.json`、2,050本）はバイト単位で v34 と同一で、デッキ・特徴・コーパス・ハイパーパラメータも一切変えていません。変えたのは v31 から続く安全シェルのガード2つです。

**実ラダー未投入です。** 以下はすべてオフラインの測定値です。

## なぜランタイムなのか

v34 は同一ホールドアウトの v33 基準線に対して test Top-1 を +5.79 ポイント動かしました（77.22% → 83.01%）。それでもラダーは900前後で、v33 の 916.9 を上回っていません。ランカーの改善がラダーに届いていない、ということです。

**v31〜v34 が報告してきた Top-1 は、すべて「ランカーの一致率」であって「エージェントが実際に打つ手の一致率」ではありませんでした。** 安全シェルはランカーの選択を破棄して v29 ベースラインに差し替えます。その差し替えが教師に近づけているのか遠ざけているのかは、一度も測られていません。

各ガードはコーパスが既に持つ列だけを読むので、シェル全体はキャッシュ済みの候補行とランカースコアから正確に再生できます（`scripts/experiment_alakazam_v35_shell_audit.py`）。実エージェントとの照合も取れています: モデルに依存しない遅延ガードの発火数は、test 先頭25試合でシミュレーション149件・実ランタイム149件で完全一致します。

結果です（test 200試合・9,977判断）。

| 指標 | 値 |
|---|---:|
| ランカーの Top-1（従来の報告値） | 83.01% |
| **実際に打つ手の Top-1** | **77.85%** |
| v29 ベースライン単体 | 65.29% |
| シェルがランカーを破棄した割合 | 16.28% |

**シェルが 5.16 ポイントを消していました。** v34 がランカー側で稼いだ +5.79 とほぼ同じ大きさです。しかも6つのガードすべてが純損失で、上位2つで83%を占めます。

## 変えた2つのガード

**`lethal_guard`**: `attack_lethal_estimate` は「相手のアクティブを倒せる Powerful Hand」であって「勝利確定」ではないので、1試合あたり約6回発火して攻撃を即座に強制していました。ランカーは79.7%で教師と一致するのに、強制された攻撃は56.4%しか一致しません（純損失 -261判断）。

待つことのリスクは Powerful Hand の火力が手札枚数に比例する点（`20 × 手札枚数`）にありますが、**それは既に `breaks_current_ko` が禁止しています**。冗長な強制でした。v35 では**強制から禁止へ**——ランカーが「ターン終了」または「非致死の攻撃」を選んだときだけ発火します。

狭めた後の発火数は**9,977判断でゼロ**です。ランカーは致死盤面でターンを終了しようとも非致死の攻撃を選ぼうともしません。**旧ガードは一度も起きない事象を防ぐために1,122回の強制攻撃を行っていた**ことになります。緩和で失う保護は測定できる範囲でゼロです。

**`preserve_fallback_boss_route`**: フォールバックが Boss's Orders を打ちたいときにランカーを常に上書きしていました。強制された Boss が教師と一致したのは **13.2%**、ランカーなら64.7%です（純損失 -168判断）。v35 ではランカーが「ターン終了」を選んだときだけ発火します。

`breaks_current_ko`・`end_with_ready_attack`・`dudunsparce_body_floor`・`unmodelled_other`・v29フォールバックはそのままです。`v29_runtime._candidate_safety_reason` にも触れていません（v29 ベースライン自身の選択がランカーの入力特徴なので、変えるとコーパスがモデルの下からずれます）。

## 結果

| シェル | test played Top-1 | test played turn-set | 破棄率 |
|---|---:|---:|---:|
| v34 | 77.85% | 94.46% | 16.28% |
| **v35** | **82.14%** | **95.22%** | **1.77%** |
| ガード全撤去（上限） | 82.98% | 95.14% | 0.17% |

**+4.29 ポイント、トレードオフなし。** validation でも同順です（76.73% → 81.92%）。turn-set も同時に上がっているので、順序の数え方で得しているわけではありません。上限との差 0.84 ポイントは `breaks_current_ko` を残した意図的な対価です。

同一モデル・同一状態で実エージェントを流した end-to-end の A/B（60試合・4,113判断、`ALAKAZAM_ML_V35_SHELL` だけを切り替え）でも **87.79% → 92.71%（+4.92）**、フォールバック率 10.75% → 1.43% を確認しています（絶対値は配備モデルが test を学習済みのため上振れします。差分が信号です）。

## 測定して却下したもの

- **教師コーパス再取得**: 5.5時間で新規13試合（+0.6%）。教師はもうほとんどラダーを回していません
- **ラベル利得の形**: 現行は 127/7/1/0 で、LambdaRank の勾配がほぼ全部ターン内順序に向いています。平坦化すると Top-1 と乖離率が単調にトレードし、順序無視の対照は turn-set 98.38% と引き換えに Top-1 が 49.85% へ崩壊します（`end` は全ターンの行動集合に入るため）。**turn-set を目的関数にしてはいけない**という対照実験として記録します
- **2段カスケード**: validation が K=3 と K=5 を0.02ポイントで分けるのに test では1.26ポイント離れます。効果はゼロと区別できません
- **`breaks_current_ko` の緩和**: +0.14ポイント。要のガードを複雑にする価値はありません
- **木の本数の増加**: validation 曲線は1,900〜2,200本で平坦

## 残差の構造（v35で新しく測ったもの）

Top-1 の誤りを回復可能性で分けました。順序誤り 10.25%（無害）、早期終了 1.88%、乖離 4.85%。**Top-1 の誤り1,695件のうち60%は無害な順序入れ替え**で、実際に効くのは672件です。回復不能件数の多い順に trainer 251、attack 108、energy 78。

`attack` の残差はほぼ全部が乖離（順序誤り1.41%）で、ラダー診断が唯一の勝敗分離量とした「Powerful Hand 4回以上の試合比率」と噛み合うクラスです。逆に `ability`（Top-1 80.09%）はほぼ全部が順序誤りで、容量を割く価値がありません。

## 検証

推論は v34 98.9 ms → v35 106.2 ms（同一セッション実測、+7.4%、p95 は 193.1 → 184.2 ms）。モデル選択率は 81.7% → **95.8%** に上がっています。

詳細は `ANALYSIS_V35.md` と `VALIDATION_REPORT_V35.md` を参照してください。

## 投入するときの見方

レートの生値では決着しません（同等エージェントで38.8ポイントの振れが観測済み）。相手 `initialScore` で条件付けた勝率と、`scripts/analyze_alakazam_v34_behaviour.py` が出す Powerful Hand 4回以上の比率（v33=58.3%）で判断してください。v35 は攻撃タイミングをランカーに委ねる版なので、**この指標が下がっていないかは特に確認が必要です**。
