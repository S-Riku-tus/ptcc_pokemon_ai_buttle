# v35 検証レポート

対象: `agents/alakazam/alakazam_ml_v35`
作成: 2026-08-02
実ラダー: **未投入**

## 1. この版の位置づけ

v35 は**ランタイムのみの変更**です。`ranker_model.json` は v34 とバイト単位で同一（sha256 `0a19b5cd564fbd4d08224c2efc9f3167a50bbd26ec9fc374aa12add6f5b7a03b`、2,050本）、コーパス・ホールドアウト境界・特徴・デッキ・ハイパーパラメータもすべて同一です。したがって v34 レポートのオフライン数値とは**直接比較できます**。

変更は安全シェルのガード2つです。

## 2. 測定方法とその妥当性

各ガードはコーパスがすでに保持している列だけを読みます（`attack_lethal_estimate`、`breaks_current_ko_estimate`、`has_ready_active_alakazam`、`self_board_count`、`v29_selected`、`action_type`）。したがってシェル全体はキャッシュ済みの候補行とランカースコアだけから正確に再生でき、別案もエージェントを組み直さずに採点できます。

ガードは全て同じベースライン手に差し替えるので、**ガードの評価順は帰属ラベルを変えるだけで、打つ手は変えません**。

**忠実性の検証（2段階）**

1. **モデル非依存ガードの完全一致**: 旧 `lethal_guard` はランカーを呼ぶ前に判定されるのでモデルに依存しません。test 先頭25試合（2,856判断）で実エージェントの `fallback_lethal_guard` は149件、同じ25試合のシミュレーションも149件。ベースライン行の同定とガード述語が実装と一致しています。判断集合も 2,856 対 2,856 で完全一致します。
2. **end-to-end の A/B**: パッケージ済み v35 エージェントを教師の観測に流し、`ALAKAZAM_ML_V35_SHELL` だけを切り替えました（60試合・4,113判断）。

| シェル | played Top-1 | played turn-set | フォールバック率 |
|---|---:|---:|---:|
| v34 | 87.79% | 98.91% | 10.75% |
| **v35** | **92.71%** | **99.85%** | **1.43%** |

差 **+4.92 ポイント**。絶対値は配備モデルが test エピソードを学習済みのため上振れしますが、両者は同一モデル・同一状態なので**差分は有効**です。オフライン推定（+4.29）と整合し、やや大きい値です。

## 5. 残差の構造（v35 で新しく定義した指標）

Top-1 の誤りを回復可能性で分けました。

- **順序誤り**: 教師も同じターンに打つ手を違う順で打った。盤面は同じところに収束する
- **早期終了**: 順序誤りのうち選んだ手がターンを終わらせる（attack / end）もの。教師のそのターンの残り行動を全部飛ばす
- **乖離**: 教師がそのターン中に一度も打たない手

| 種類 | 割合 | 判断数 |
|---|---:|---:|
| 一致 | 83.01% | 8,282 |
| 順序誤り（無害） | 10.25% | 1,023 |
| 早期終了 | 1.88% | 188 |
| 乖離 | 4.85% | 484 |
| **回復不能** | **6.74%** | **672** |

Top-1 の誤り 1,695件のうち **60% は無害な順序入れ替え**です。回復不能件数の多い順: trainer 251、attack 108、energy 78、ability 46、bench 42、evolve 37、boss 35、xerosic 34、end 20、retreat 16、hammer 5。

`attack` は順序誤り 1.41% / 乖離 11.68% でほぼ全部が回復不能、`ability` は Top-1 80.09% でも回復不能は 2.90% です。v34 が挙げた「boss 47.94% が突出して低い」は、52ポイントの誤りのうち 34 ポイントが順序誤りなので見た目ほど悪くありません。

## 8. テストと静的検証

- `pytest agents/alakazam/alakazam_ml_v35`: **204件成功・0失敗**（v34 は188件、v35 で16件追加）
- `scripts/validate_agent.py --agent alakazam_ml_v35`: **成功**（警告0）

`test_v35_runtime_logic.py`（14件）が固定するもの:

- 致死盤面で非終了の手が通ること／`end` と非致死攻撃は依然拒否されること／致死攻撃自体は通ること
- 致死盤面でも `breaks_current_ko` が効くこと（緩和の根拠）
- Boss ルートが `end` 以外を阻まなくなったこと、`end` には効くこと
- 変更していない4ガード（`unmodelled_other`、`end_with_ready_attack`、`dudunsparce_body_floor`、3体以上なら Dudunsparce 循環可）
- **狭めた関数が共有版と、意図した2箇所以外では総当たりで一致すること**
- 既定シェルが v35、`ALAKAZAM_ML_V35_SHELL=v34` で旧挙動に戻ること
- 配備モデルが v34 とバイト同一（2,050本）であること

`test_v15_runtime_logic.py` の環境変数テストは、ソース文字列の grep から挙動検査へ置き換えました。v35 は版チェーンをループで読むためリテラル名がソースに現れませんが、v31〜v35 のすべての名前が有効であることを実際に確認しています。

## 9. 推論コスト

同一セッションで両エージェントを同じ289件の scoped 判断に対して実測（メモリ非ヒット）。

| 指標 | v34 | v35 | 差 |
|---|---:|---:|---:|
| mean | 98.9 ms | 106.2 ms | +7.4% |
| median | 93.1 ms | 101.1 ms | +8.5% |
| p95 | 193.1 ms | 184.2 ms | -4.6% |
| max | 242.3 ms | 225.5 ms | -6.9% |
| **モデル選択率** | 0.8166 | **0.9585** | +14.2pt |
| フォールバック率 | 0.1834 | **0.0415** | -14.2pt |

旧 `lethal_guard` はランカーを呼ぶ前に打ち切っていたので、緩和するとその分だけモデルが余計に走ります。mean +7.4% はその代償です。p95 と max が下がっているのは測定ノイズの範囲と見ています。

この測定の v34 値（98.9 ms）は v34 レポートの 135.0 ms と異なりますが、これはマシン負荷の差です。同一セッション内の相対比較のみを使ってください。

ランタイムは `remainingOverageTime` が 2.0 秒を切ると決定論的方策に退避します。

## 11. 既知の限界

1. **実ラダー未投入。** すべての主張は教師のホールドアウト状態での一致率です。v31〜v34 が報告していた「ランカーの一致率」より確実にラダーに近い量ですが、依然として代理指標です。
2. **「v34 のオフライン利得がラダーに届いていない」という前提は暫定です。** レート900前後という観測に基づいていますが、v33 の 916.9 との差は同一エージェントで観測された振れ（842.8 対 804.0）の中にあります。v34 が確定したら測り直しが必要です。
3. **PH 4回以上の比率は下がる見込みです**（第4節）。これを退化と解釈しないでください。
4. **ランカーは無変更なので、90% 目標は未達のままです**（83.01%）。回復不能な誤り672件も手つかずです。
5. `breaks_current_ko` を残した 0.84 ポイントは、安全性と引き換えの意図的な支払いです。
6. ラダーのノイズ床は n≈60 で約40ポイントなので、**1ランでは確認できません**。
