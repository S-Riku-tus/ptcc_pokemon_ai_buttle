# v36 分析

## 結論

v36では、v35の残課題である行動種選択を改善するため、従来の「行動種内の最高候補6属性」だけではなく、各行動種に属する候補集合全体から戦術情報を集約するrich type representationを実装した。

時系列分離testにおける最終Top-1は81.62%で、v35の81.60%から2判断、+0.02ポイントの改善だった。目標90%は未達であり、統計的・実戦的にv35を明確に上回ったとは扱わない。

## 出発点

v34候補rankerはtest Top-1 80.63%、Top-2包含率93.30%だった。v35では行動種分類を加え、正しい行動種が既知なら候補選択95.59%、最終Top-1 81.60%となった。

このためv36では、候補生成や同一種内順位ではなく、「ability、attack、bench、energy、evolve、trainerなどのうち、今どの種を実行するか」を主要な改善対象とした。

## 検証した仮説

### 1. 合法行動種を直接順位付けするtype-level LambdaRank

行動種を候補として直接順位付けしたが、validationは約84.1%でv35を超えなかった。候補数が少ない一方、同一ターンの順序依存を十分に表せなかった。

### 2. CatBoostおよび量子化方策記憶

CatBoostはvalidation約84.0%だった。盤面を量子化した近傍・署名記憶はvalidationで一時84.66%まで上がったが、testで再現せず不採用とした。

### 3. Majkel上位教師の低重み追加

Majkelログ10,275判断を抽出し、重み0.03〜0.10で補助学習した。validationの最大改善は約+0.16ポイントだったが、testでv35を下回ったため本体へ入れていない。教師間の手順差を単純混合しても、Yushin模倣精度は上がらなかった。

### 4. マルチタスク計画モデルとType-Set neural model

「このターンで攻撃へ到達するか」「残り手数」を補助教師にしたMLP、行動種ごとに候補集合をpoolするType-Setモデルを試した。いずれもvalidationでv35を超えず不採用とした。

### 5. rich type representation

v35の276入力を監査すると、行動種ごとの候補情報は主にv34スコア統計と最上位候補の6属性だけだった。v36では各行動種について次を追加した。

- リーサル候補、現在のKOを壊す／維持する候補
- 行動後の手札、Powerful Hand打点、KO推定
- 手札コスト、純手札増減、通常・進化・リッチエネルギーのドロー量
- 攻撃エネルギー、最初のケーシィ、Stage 2、進化ルート不足を埋めるか
- 候補位置、カード種類数、対象種類数
- 対象HP、特殊エネルギー、配置場所

完全表現は1,052値になった。validationだけで追加特徴を選択し、v35互換の276特徴と重要な追加80特徴、合計356特徴へ圧縮した。

## 最終モデル

- XGBoost multiclass
- 11クラス
- 356選択特徴
- 2,497木
- train+validation 40,742判断で最終fit
- confidence 0.50以上の場合だけ行動種ゲートを適用
- 同一行動種内はv34 LambdaRankで順位付け
- 低確信時はv34順位へ戻る

trainのみで選択した構成はvalidation行動種84.64%、最終Top-1 81.70%だった。構成とthresholdを固定後、train+validationで再学習し、testを評価した。

## 最終結果

| 指標 | 結果 |
|---|---:|
| v34 test Top-1 | 80.63%（7,134 / 8,848） |
| v34 test Top-2 | 93.30%（8,255 / 8,848） |
| v35 test Top-1 | 81.60%（7,220 / 8,848） |
| v36 test行動種精度 | 84.86%（7,508 / 8,848） |
| 正解行動種内の候補選択 | 95.59%（8,458 / 8,848） |
| **v36 test Top-1** | **81.62%（7,222 / 8,848）** |
| 目標 | 90%以上 |

v36はv35より2判断多く一致しただけである。さらに行動種精度自体はv35の84.88%とほぼ同じで、わずかに低い。rich表現はvalidationでは改善したが、testへの一般化改善はほぼゼロだった。

## 90%未達の意味

現在の公開盤面特徴、sequence履歴、木モデル、候補集合pool、教師混合の範囲では、モデル群のvalidation行動種oracleも約87.9%に留まった。正解を見て最良モデルを選ぶ上限さえ90%を下回るため、同じデータとモデル族の再調整だけで90%へ到達する根拠はない。

次に必要なのは次のいずれかである。

1. 同一教師の新しい完全未閲覧ログを増やし、手順の反復を学ぶ
2. 1判断ではなく、ターン終了または攻撃までの行動列を直接教師にする模倣プランナー
3. 合法手を実際に適用した後の盤面を生成し、残りルート価値を評価する遷移モデル
4. 教師の同価値行動を単一正解ではなく複数正解として扱うラベル再定義

## 判断

v36は90%達成版ではない。安全性とruntime再現性を保った研究challengerとして保存するが、v35に対して明確な昇格根拠はなく、実戦championはv31のまま維持する。
