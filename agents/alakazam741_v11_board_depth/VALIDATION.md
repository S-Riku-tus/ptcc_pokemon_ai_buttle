# Validation — v11.1

## 実行済み

- `main.py` / `policy_base.py` / テストのPython構文検査
- デッキ60枚検査
- 現在のカード枚数検査
- 未知カードID検査
- 基本エネルギー以外の4枚制限検査
- ACE SPEC重複検査（ハイパーアロマのみ1枚）
- 重複関数定義検査（`main.py`）
- API互換スタブによるGolden-stateテスト25件
- フルZIP解凍後の再テスト
- 提出ZIPのルート直下3ファイル検査

## Golden-stateの主な対象

- 現在の60枚が起動時デッキ検査を通る
- ハイパーアロマとエンリッチエネルギーを同時に含む仮想デッキを拒否
- 未知カードIDを拒否
- 非基本エネルギーを含む同名5枚投入を拒否
- 後攻序盤は3経路を目標にする
- 資源不足のケーシィを完成済み経路と数えない
- 必要な本体数に達した後は追加ケーシィを低評価にする
- キチキギスexを有効な代替攻撃役として扱う
- キチキギスexの途中給エネを許可するが、主フーディン経路より先にはしない
- シェイミはベンチ攻撃脅威時だけ展開する
- シェイミが場にいる時はバトルケージを使わない
- 改造ハンマーは2エネルギー不足を作れる時だけテンポ使用する
- 1エネルギー不足しか作れない改造ハンマーを拒否する
- 手札だけのケーシィ＋ユンゲラー＋フーディンを完成ルート扱いしない
- バトルケージでPowerful Hand 20を0にしない
- 非ミラークセロシキを拒否する
- 攻撃可能時のENDを拒否する
- 夜のタンカ2回目は直接改善がない場合に拒否する

## 未実施

この環境には実プロジェクトの`vendor/cg`と対戦ハーネスがないため、実エンジン対戦、同一seed席順交換、Kaggle Rating確認は未実施。スタブ検証はAPI経路と判断条件の整合性を確認するもので、実戦性能を保証するものではない。
