# 設計・分析 V1

## 1. 教師データの同定

対象は `data/runs/leaderboard_top1/non_alakazam/20260801_rank01_sub55137818` です。manifest 396行のうち正常なreplayは386、取得エラーは10でした。各replayについて、manifestの `detected_submission_agent_index` とreplay内 `TeamNames` を突き合わせ、`Majkel1337` の座席を決定しました。seat 0/1を固定値で仮定していません。

教師座席の初期観測から60枚を復元し、386試合すべてが同じdeck signatureであることを確認しました。デッキ不一致は0です。先攻・後攻の選択が観測できた194件では、教師はすべて先攻を選択していました。

## 2. コーパス化

ゲームログの時刻 `t` の観測と `t+1` の教師actionを対応させます。主行動だけでなく、手札・ベンチ・入替・サーチ・捨て札・攻撃・複数選択数を含む全select contextを対象にしました。

- 正常試合: 386
- 意思決定: 32,497
- 合法候補行: 294,627
- 非強制意思決定: 30,848
- 複数選択: 2,199
- 選択数が可変: 4,177
- 生特徴量: 749
- train上で変動する特徴量: 543

分割はファイル順の時系列で train 296 / validation 40 / test 50 試合です。同じ試合の局面が複数splitへ入らない episode split なので、局面単位のランダム分割による漏洩を避けています。

## 3. 特徴量とリーク対策

特徴量は、その意思決定時点でagentに渡される観測と合法候補だけから作ります。次の教師action、将来のstate、最終勝敗、episode ID、split IDは入力しません。特徴量名にもdenylist検査を入れています。

主な情報は、手札・山札・トラッシュ・場・ダメージ・エネルギー・進化可否、相手盤面、同一ターンの行動履歴、LopunnyのBench→Active移動、Gale Thrustの170追加条件、Dudunsparceの循環、trainer/supporter/energy使用状況、候補カード・対象・攻撃・入替先との交差です。

## 4. 学習設計

合法候補は候補数が局面ごとに異なるため、固定クラス分類ではなくgroup-wise LambdaRankを採用しました。複数選択数は別のL1回帰で推定します。

木数は次の順で選びます。

1. trainだけで最大1200木のrankerと最大500木のcount modelをfit。
2. rankerは50木刻み、count modelは25木刻みでvalidationを評価。
3. rankerはvalidationの非強制semantic exact、countは可変選択数accuracyで固定。
4. testは選択後に一度だけ評価。
5. 配布モデルは、固定した900木/200木で全386試合に再fit。

最近の教師方針を重くするため、古いepisodeにも0.4を下限とする二乗recency weightを与えています。

## 5. 結果と解釈

正しい一般化評価は、全データ再fit前の時系列testです。

- 非強制semantic exact: 77.13%
- 非強制raw exact: 73.33%
- 単一選択Top-1: 77.73%
- 単一選択Top-2: 92.23%
- 単一選択Top-3: 97.30%
- 主行動Top-1: 73.44%
- 可変選択数accuracy: 99.63%

文脈別では `ToHand` が91.06%、switchが88.34%まで届く一方、主行動が73.44%、複数枚discardの完全一致が38.64%です。選択枚数はほぼ解けているため、ボトルネックは「何枚選ぶか」ではなく「どれをどの順で選ぶか」です。

選択順の違いを弱く扱うgraded relevanceも検証しました。turn内で後から教師が選ぶ候補まで正解集合とみなす `turn-set` は90.60%でしたが、厳密な次actionは76.05%へ悪化しました。このためgraded modelは配布せず、binary modelを採用しました。これは、候補集合の認識は9割を超えているが正確な順序決定が不足している、という診断です。

全386試合へ再fitした配布モデルを既知testログに戻すとsemantic exact 90.21%です。これはランタイムの特徴量・木評価・semantic変換が学習系と整合する証拠ですが、学習済みデータへの再代入なので未知試合の性能証拠ではありません。

## 6. v33/v34との比較から分かること

添付記録のフーディンv34は2,268試合でtest strict Top-1 83.01%でした。本データは386試合で、その約17%です。デッキが異なるため数値は直接比較できませんが、386試合から未知局面9割を期待する根拠はありません。モデルをさらに複雑にするより、同一submission・同一deckの新しいログを継続取得する方が先です。

## 7. 次段階

優先順位は次の通りです。

1. 教師submission/deck signatureを毎回検証しながら、最低2,000試合規模まで追加する。
2. 最新試合を固定testとして隔離し続け、testを見て木数や特徴を選ばない。
3. Top-3内の再順位付けを行う第2段モデルを、OOF予測だけで学習する。
4. 主行動と複数discardを別ヘッドに分離し、集合選択と順序選択を別指標で最適化する。
5. 90%到達後に初めて公式環境の勝率・クラッシュ率・時間制限を大規模検証する。

現時点での判定は `holdout_target_not_met` です。既知ログ9割という数字だけで提出候補へ昇格させないことが、今回の評価設計の結論です。
