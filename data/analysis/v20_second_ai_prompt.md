## 0. 競技とデッキの前提

- 勝利条件: 相手のサイド6枚を取る。KO時のプライズ値は **メガex=3 / ex=2 / 通常=1**。
- 対象デッキ: フーディン（Alakazam）。主要カード:
  - Abra(741)→Kadabra(742)→Alakazam(743) 進化ライン。245 は Alakazam の攻撃型。
  - **Alakazam の主力技 Powerful Hand = 20 × 自分の手札枚数ダメージ**（手札=火力）。
  - Fezandipiti ex(140): 2プライズのドローエンジン（唯一の2プライズ負債）。
  - Dunsparce/Dudunsparce: Run Away Draw（+3ドロー、自身は山札へシャッフル）。
  - Boss's Orders(1182): 相手のベンチを1体アクティブに引きずり出すサポート。
  - Xerosic(クセロシキ): 相手の手札を3枚に減らすサポート（**ミラーでは相手のPowerful Handを破壊**）。
- 大会上位プレイヤーのインタビュー由来の核心思想:
  **「手札枚数が命。Powerful Hand が手札依存なので、Xerosic 等で手札を削られると火力が壊れる。
  だから手札はむやみに増減させず、倒したい相手の残HPに合わせて最適化する。」**

## 2. アーキテクチャの重要事実（検証済み）

- ML(`HybridRanker`, threshold 0.37)が上書きするのは `ML_ALLOWED_ACTIONS = {"bench","evolve"}` のみ
  （`ml_runtime.py:19-35`）。**Boss / attack / trainer / energy / ability / retreat は決定論的 fallback**。
  → 今回の3要件は **fallback スコア関数の改修で完結し、ML 再学習は不要**（この事実を必ず検証せよ）。
- fallback は `PolicyEngine._score(o)`（`fallback_policy.py:2222`）で全オプションをスコア→最大選択。
- 既存の KOルート探索 `_active_route_plan()`（`:1604`）は **相手Active限定**の最小確定KO手順を bitmask 探索。

## 3. サイド6枚の取り方 分析の結論（既存, 前提として使う）

- **少なく・高価値のKOほど速い**（top40, 勝者構成別 平均ターン）:
  3+3(2KO)=9.9T / 2+2+2(3KO)=11.6T / 2+2+1+1(4KO)=12.8T / 2+1+1+1+1(5KO)=14.7T / 1×6(6KO)=17.5T。
  → KO 1回増ごとに約 +1.5〜2 ターン。
- 相手アーキ別（勝者視点）: メガ 3.25KO/11.4T、ex 5.29KO/14.5T、単 6.22KO/18.2T。
  フィールドの約68%が ex 相手 → 現実的最頻ルートは **2+2+1+1 / 2+2+2**。
- vs ex で2プライズ体を取る試合は取らない試合より **KO −1.4回・ターン −1.6**（大物を能動的に落とす価値）。
- 自 v19 固有: Fezandipiti ex(140) が唯一の2プライズ負債（52戦中6回KOされ、相手のレースを前倒し）。
  相手別勝率: 単69% / メガ62% / **ex 52%（最大母数かつ最も競っている）**。
- caveat: KO帰属は Dudunsparce 自己シャッフルを単KOに過大計上しうる（ターン数・相手アーキ指標は無影響）。

## 4. 分析してほしい3要件（ユーザーの改修意図・原文の要約）

### 要件① Boss's Orders の絶対条件
> サイド枚数が **2 or 3枚** の時、相手ベンチのHPと自分の与ダメージが足りていて、
> **サイドを全て取れる時に Boss を使う**（絶対条件として）。

### 要件② 手札枚数のより良い最適化
> Powerful Hand が手札依存なので手札=命。Xerosic 等で削られると火力が壊れる。
> **倒したいポケモンの残HPを踏まえて手札枚数を最適化**し、むやみに増やさない/減らさない。
> （現状の最適化がどの程度効いているかは不明。上位は Run Away Draw の発動が少ない。）

### 要件③ ターゲット優先順位付け → 最優先から順にKOルート探索
> ターン開始（1ドロー後）時点で「どのポケモンを倒すべきか」の優先度が決まっているはず。
> 優先度は **自分と相手のサイド枚数比較 + 双方の場/ベンチの構成** から計算できる。
> 最優先の相手ポケモンを、手札のカード使用や場のやりくりでどう倒すか判断 → 無理なら次点へ、
> という順で考えるのが分かりやすい。各カードの使用条件はそこに乗る形。
