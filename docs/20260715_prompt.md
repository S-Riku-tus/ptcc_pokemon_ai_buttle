# 1. 背景と最終目的

これまでフーディンデッキを、主に手書きのスコアリングロジックと多数の条件分岐で制御してきました。

しかし、ロジックを複雑化するほど、

* 攻撃前に検索・展開・回収を行いすぎる
* 攻撃開始が遅れる
* 必要以上に手札を増やす
* 山札切れが増える
* キチキギスexやシェイミなどの補助カードへ資源を使いすぎる
* 条件同士が競合する
* 対面別例外が増え、汎化性能が下がる

という問題が起きました。

過去の主な結果は次の通りです。

* v9は初攻撃、攻撃率、退避制御が比較的良好だった
* v11は盤面全滅を多少減らしたが、初攻撃が遅れ、検索・ドロー・山札消費が増えた
* 現在1位Majkel1337のフーディンは、v11より手札枚数と過剰打点が少ない一方、攻撃回数、サイド取得、Boss、Hammer、ノココッチ循環、別アタッカー運用が良好だった
* Majkelの最新ログでは、完了163試合で129勝34敗、勝率約79.1%だった
* Majkelログの簡易模倣学習では、試合単位の時系列分割に対し、メイン行動の意味的Top 1一致が約68%、Top 3が約87%となり、上位方策に機械学習可能な一貫性が確認された

最終目的は次の通りです。

> 上位50位までに存在する複数のフーディンエージェントのログを、信頼度付きの教師データとして統合し、合法手候補を評価する模倣学習モデルを作る。
> 確定安全処理はルールとして残し、手書きスコアが苦手とする優先順位判断をモデルへ置き換える。
> その後、ローカル対戦が可能なら自己対戦・強化学習で上位方策を改善し、Kaggleへ提出可能な軽量エージェントを作る。

# 3. 最重要の設計原則

## 3.1 上位の行動は「高品質な正解候補」とする

基本方針として、上位チームが選んだ行動は強い教師データとして扱ってください。

特に、

* 上位チーム
* Ratingが高い提出
* 勝利試合
* 複数の上位チームが類似状態で同じ行動を選ぶ
* 行動後に攻撃、KO、サイド取得、後続維持へつながっている

場合は、高い信頼度を与えてください。

ただし、

> 勝利試合の全行動を無条件の絶対正解にはしない

でください。

勝利試合にも、

* 相手の事故によって勝った
* 良くない行動を後から挽回した
* 勝敗に影響しない行動を選んだ
* 勝利確定後の行動
* 同等な複数候補のうち一つを選んだ

場合があります。

したがって、各意思決定へ教師重みを付けてください。

## 3.2 敗北試合も利用する

敗北試合をすべて除外しないでください。

敗北試合には、

* 初手事故からの最善に近い復帰
* 不利対面での防御
* 攻撃役を失った後の再構築
* 山札が少ない終盤判断
* ロック対面での行動
* 正しい行動をしても引きや相手展開で負けた局面

が含まれます。

敗北試合は勝利試合より教師重みを下げつつ、Policy学習とValue学習の両方に使ってください。

# 8. 教師重み

初期値の例として、以下を用いて構いません。

| 教師          | 初期重み |
| ----------- | ---- |
| 1～5位の勝利試合   | 1.00 |
| 6～15位の勝利試合  | 0.90 |
| 16～50位の勝利試合 | 0.75 |
| 1～5位の敗北試合   | 0.60 |
| 6～15位の敗北試合  | 0.50 |
| 16～50位の敗北試合 | 0.35 |
| 異常終了・タイムアウト | 0    |

ただし、この値を固定の正解とせず、検証データでアブレーションしてください。

最終的な教師重みは概念的に、

```text
教師重み
=
順位・Rating重み
× 勝敗重み
× データ品質
× 局面重要度
× 行動後品質
× 上位間合意度
```

としてください。

重みは極端になりすぎないようクリップしてください。

## 8.1 局面重要度

高くする候補：

* 勝利KO
* 通常KO
* Bossの対象選択
* 改造ハンマー
* クセロシキ
* エネルギー貼り先
* ふしぎなアメかユンゲラーか
* 最初の攻撃役完成
* 後続フーディン完成
* 山札残量が少ない終盤
* ロック対面でのキチキギスex育成
* 攻撃か追加ドローか
* 退避するか
* サイド取得へ直結する行動

低くする候補：

* 唯一の合法手
* 同一カードserialの違い
* 勝利確定後の重要度が低い行動
* 意味的に同等な対象
* ゲーム結果へほぼ影響しない強制選択

唯一の合法手は、学習から除外する場合と軽い重みで含める場合を比較してください。

## 8.2 行動後品質

将来情報はモデル入力には入れませんが、教師重みの計算には利用可能です。

行動後に以下が成立した場合は加点候補です。

* 同ターン攻撃
* 同ターンKO
* サイド取得
* 勝利
* 次ターン攻撃可能な後続が成立
* 相手の次ターン攻撃を止めた
* Bossで高価値対象を倒した
* Hammerで重要特殊エネルギーを剥がした
* ロック対面で別攻撃経路が成立

減点候補：

* 攻撃可能だったのに補助行動だけで終了
* KO打点を手札消費で失った
* 後続なしで主攻撃役を失った
* 不要な部分給エネ
* 山札切れ直前の過剰ドロー
* 盤面全滅へ直結
* 効果無効への0ダメージ攻撃
* Boss、クセロシキ、Hammerを使ったが目的を達成しなかった

勝利試合でも、明確に品質の低い行動には満点を与えないでください。

# 11. モデル開発

最初から大規模Transformerや純粋な強化学習へ進まないでください。

比較する最低限のベースライン：

1. 先頭合法候補
2. 行動種別頻度
3. 手書きスコア
4. LightGBM／XGBoost系の候補ランカー
5. 小型ニューラル候補ランカー

LightGBMなどを学習に使って構いませんが、最終提出環境で使えるとは限りません。

## 11.1 推奨モデル

候補スコアリング型にしてください。

```text
状態エンコーダ
＋
合法候補エンコーダ
→
候補スコア
```

推奨構成：

* カード埋め込み
* ゾーン埋め込み
* 手札はDeepSetsまたは集合Pooling
* ActiveとBenchは小型Attentionまたは共有MLP＋Pooling

* 候補ごとのMLP
* 合法候補内softmax
* Value Head
* 補助タスクHead

モデルを過大にしないでください。

## 11.2 学習目標

最低限：

* `Policy loss`
* `Value loss`

可能なら補助タスク：

* 今ターン攻撃するか

* 山札切れ危険
* 盤面全滅危険
* Boss後KO
* Hammer後に相手が攻撃可能か
* キチキギスex完成ETA
* ノココッチ使用後に再展開可能か

Policy lossには教師重みを適用してください。

# 14. ハイブリッドエージェント

最初の提出候補は、モデル単独ではなくルールとのハイブリッドにしてください。

維持する確定安全処理：

* 合法手以外を選ばない
* 不正なデッキを拒否する
* 60枚、同名4枚、ACE SPEC制限
* 最後の1体ノココッチで盤面を消さない
* 効果無効への0ダメージPowerful Handを選ばない
* 現在の勝利KOを不要な手札消費で崩さない
* サポーター使用制限
* エネルギー型の合法性
* 同一ターンの不正な複数使用防止
* タイムアウト直前の高速フォールバック
* モデル出力異常時のフォールバック
* 例外時の合法候補選択

推論手順：

```text
1. 全合法候補を取得
2. 明確に危険・無意味な候補を安全ルールで除外
3. 残った候補をモデルが評価
4. モデル確信度が閾値以上ならモデル選択
5. 低信頼なら既存ロジック
6. 最終合法性検査
```

モデル適用範囲は段階的に広げてください。

第一段階：

* 攻撃
* 特性
* 進化
* 検索対象

第二段階：

* エネルギー
* ヒカリ／ヒルダ
* ふしぎなアメ
* ノココッチ

第三段階：

* Boss
* Hammer
* クセロシキ
* 退避
* ロック対面

# 15. デッキは最初に変更しない

最初のモデル評価では、Majkelの最新60枚を正確に再現し、デッキ変更を行わないでください。

モデルとデッキ変更を同時に行うと、改善原因を判定できません。

まず、

* Majkel型60枚
* 手書きロジック
* Majkel模倣モデル
* ハイブリッドモデル

を比較してください。

デッキ探索は、モデル方策が安定してから別フェーズで行ってください。

# 17. 自己対戦・強化学習

模倣モデルが実対戦で安定した後だけ実施してください。

最初からランダム方策で強化学習しないでください。

推奨順序：

```text
上位模倣学習
→ ハイブリッド対戦検証
→ 模倣モデルを初期値にした自己対戦
→ 上位方策から離れすぎないよう模倣損失を残す
```

利用可能なら、

* Recurrent PPO
* 合法手マスク
* Policy＋Value共有エンコーダ
* リーグ自己対戦
* 過去チェックポイント
* 上位模倣モデル
* 苦手対面エージェント

を組み合わせてください。

相手プールの一例：

* 30% 上位模倣モデル
* 20% 過去チェックポイント
* 20% 苦手対面
* 20% 最新モデル
* 10% 多様化した方策

ただし、対戦速度が不十分、環境コピーが困難、再現性が低い場合は、無理に強化学習を完了したことにしないでください。

その場合は、模倣学習＋Value＋浅いロールアウトまでを完成させ、未実施部分を明示してください。

# 18. 提出環境への対応

学習環境で使えるライブラリと、Kaggle提出環境で使えるライブラリを分けて確認してください。

最終推論では、外部依存を可能な限り減らしてください。

候補：

* NumPyのみの小型MLP
* 重みをPython定数として埋め込む
* 純Python推論
* 決定木への蒸留
* 小型線形／MLPモデル
* モデルファイルを提出ZIPへ同梱できる場合のみ同梱

LightGBM、PyTorch、scikit-learnが提出環境にあると仮定しないでください。

最終提出ZIPの構造は、既存の正常提出例と競技ルールを確認してください。

不要なファイル、`__pycache__`、`.pyc`、学習データ、巨大ログを提出ZIPへ含めないでください。

# 19. 必須テスト

## データテスト

* 観測とactionの時系列対応
* actionが合法候補内にある
* 両プレイヤー観測の混入がない
* 相手手札リークがない
* 重複試合除外
* 欠損処理
* タイムアウト除外
* デッキハッシュ整合
* 同じepisodeが複数splitへ入らない

## モデルテスト

* 候補数が1件
* 候補数が多い
* 未知カードID
* 未知対戦相手
* 空履歴
* モデル重み読み込み失敗
* NaN／inf
* 全候補が安全ルールで除外された場合
* 決定的seedで再現可能
* 推論時間上限

## Golden-stateテスト

少なくとも次を含めてください。

* 確定勝利KOを選ぶ
* 効果無効への0ダメージ攻撃を選ばない
* 最後の1体ノココッチ特性を選ばない
* ケーシィ不在時に適切な検索を行う
* 最初の攻撃役完成前に不要な3本目を追わない
* 初回フーディン完成時にアメを適切に使う
* KO打点到達後に不要なドローを止める
* Bossで高サイド対象をKOできる場合
* Hammerで重要特殊エネルギーを剥がす場合
* キチキギスexをロック対面で完成させる場合
* キチキギスexへの無意味な部分給エネをしない
* 山札切れ直前に過剰ドローしない
* 非ミラーの無意味なクセロシキを使わない
* 意味ある非ミラークセロシキを候補にできる
* 低信頼時に既存ロジックへ戻る
* 不正・例外時も合法手を返す
