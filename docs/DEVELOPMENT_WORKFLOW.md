# 開発サイクル

1. 新版フォルダを作る
2. 変更点を一つに限定する
3. `validate_agent.py`を通す
4. ローカルで最低100試合実行する
5. 相手デッキ別に勝率を比較する
6. Replayを目視確認する
7. `experiments/results.csv`へ記録する
8. Pull Requestでレビューする
9. `main`へマージする
10. タグを付けてKaggleへ提出する

## 判定時の注意

20～30試合程度ではカードの引きによるばらつきが大きいため、変更採用の判断には
相手ごとに80～100試合程度を推奨します。

勝率だけでなく、以下も記録します。

- エラー・時間切れ
- 先攻勝率、後攻勝率
- 平均ターン数
- 攻撃可能なのに攻撃しなかった回数
- 不要なカードを捨てた回数
- エネルギー付与先の失敗
- 特定デッキに対する0ダメージ行動
