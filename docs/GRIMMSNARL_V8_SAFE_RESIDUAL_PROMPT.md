## 実施手順

### 1. v8を凍結した基準にする

- v8本体、デッキ、モデル、ルール層、planner、テストを読み、行動経路を整理する。
- 新v10の作成前にv8の対象テストを実行し、基準結果を保存する。
- 新v10のデッキと、差分対象外のファイルがv8と同一であることをハッシュで確認する。
- 既存のv8/v9やユーザーの無関係な変更を編集しない。

### 2. v8の実戦失敗を意思決定単位で分析する

- 全50 rated gamesを、相手レート帯、相手deck hash、先攻後攻、時系列に分けて再集計する。
- Alakazamの6敗を最優先に、v8の実行行動と、v8・v9・現トップ複数教師モデルの反実仮想行動を同一盤面上で比較する。
- MAINだけでなく、手貼り、攻撃可能化、進化、Boss、Unfair Stamp/Petrel、攻撃対象、サイド取得に直結する全contextを調べる。
- 単発の違いではなく、複数敗戦で繰り返され、勝利ログまたは上位教師の複数合意で支持される差だけを改善候補にする。
- Alakazam戦の問題がプレイで回収可能か、デッキ構造上の限界かを分離する。説明できない相関を因果的な修正として実装しない。

### 3. 全面模倣ではなく安全な残差方策を作る

- 通常はv8の選択をそのまま返す。
- 上書きは、対象context、盤面条件、複数助言器の合意、校正済みmargin/OOD条件をすべて満たす場合だけ許可する。
- 上書き率は目的にせず、検証可能な単一桁%程度の限定的な差分から始める。閾値はvalidationで決め、testへ合わせ込まない。
- 少なくとも次の安全ゲートを実装する。
  - 合法な手貼りを不必要に失わない。
  - そのターンの攻撃を可能にする手貼りを失わない。
  - 明確に有効なGrimmsnarl進化とFroslass進化を減らさない。
  - 確定KO、最大サイド取得、明らかな攻撃可能行動を弱い候補で上書きしない。
  - 助言器の失敗、欠損、低信頼、未知盤面では必ずv8へ戻る。
- deck hashだけのハードコードにせず、相手盤面のカード・脅威・サイド・エネルギー・到達可能な攻撃を特徴として使う。
- すべての上書きについて、context、v8候補、採用候補、合意数、margin、安全ゲート、理由を診断カウンタへ記録できるようにする。

### 4. 状態分布のずれを抑える

- 上位教師ログだけで学習せず、v8の広い既存コーパスと、今回のv8実戦で到達した盤面を混ぜる。
- 必要ならDAgger型に、候補方策がローカルで到達した盤面を収集し、複数教師・v8・明示ルールで再ラベルする。
- 単一教師IDを方策全体の正解にしない。教師間で不一致の盤面は原則v8維持、または学習対象外にする。
- 勝利試合への単純な重み付けだけで方策改善とみなさない。相手強度、盤面、対面、到達状態の交絡を考慮する。

### 5. 相手パネルと評価を改善する

- 保存済みの相手側観測・行動から、Alakazam、mirror、M Lopunny + M Froslass、Dragapult、Ogerponの対戦パネルを作る。
- 相手模倣はraw MAIN Top1だけでなく、順序非依存Top1、Top-k、意味的行動クラス、資源行動、攻撃選択を評価する。
- 模倣精度が低い相手は絶対勝率の根拠にせず、v8と新v10を同一seed・同一席順で比較する回帰検出器として使う。
- 8戦程度のarena結果を採用根拠にしない。可能な範囲で十分なpaired gamesを回し、勝率差とWilson区間を出す。

## 合格条件

- クラッシュ、timeout、illegal actionが0。
- デッキハッシュがv8と完全一致。
- v8の全既存対象テストに回帰がなく、新しい残差ゲートの単体テストがある。
- v8実戦盤面上で、手貼り、攻撃可能化、Grimmsnarl進化、Froslass進化を既知のv8基準から実質的に悪化させない。
- Alakazam敗戦盤面に対する上書きが、複数試合で反復し、複数の独立した根拠で支持される。
- mirrorや1000未満相手でv8の強みを壊す兆候がない。
- teacher-forced Top1だけで合格にしない。閉ループ、同一盤面反実仮想、資源安全性、対面別paired比較を総合する。

合格条件を満たす改善が見つからない場合は、v8と同一の見せかけの新バージョンを作らないでください。失敗した仮説と証拠を残し、次に必要なデータまたは設計変更を明記してください。
