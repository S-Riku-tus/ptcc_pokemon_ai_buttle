## 方法論上の重要な発見: action↔observation の対応

リプレイ `steps[i]` の観測(select)に対するエージェントの応答は、**`steps[i+1]` の
`action` に記録されている**。v3ポリシーをリプレイ観測に再適用して照合した結果、
MAIN決定は i+1 側とほぼ完全一致し、同step側はほぼ不一致だった。

これが重要な理由: 誤対応(同step)で集計すると存在しない悪手が大量に検出される。
実際、誤対応では「致死なのに攻撃せずEND: 130件」「ボス無駄撃ち: 30件」と出たが、
**正対応では両方とも0件**。v3の致死維持ゲート(P0-1)とボスのKOゲートは機能していた。
今後のrun分析は必ず `experiments/v3_run_analysis/analyze_v3_deep.py` の方式
(i+1対応 + ポリシー再実行での照合)を使うこと。

## 敗因の全数分類 (21敗)

負け試合の「自分が攻撃できなかったターン」39ターンを状態から機械分類:

| 分類 | ターン数 | 意味 |
| --- | ---: | --- |
| **場にフーディン不在 (no_alakazam_built)** | **34** | 被KO後にラインが再建できない |
| 前詰まり (powered_on_bench_stuck) | 3 | ユンゲラー0エネActive+ベンチに攻撃可能フーディン |
| エネ切れ (alakazam_no_energy) | 2 | |

典型パターン(85323707, 85333966など): フーディン被KO → ユンゲラー昇格(80HP) →
一撃で狩られる → ケーシィ昇格(50HP) → 狩られる… を繰り返し、30/10ダメの攻撃で
300-440HPのex/メガに挑み続けて敗北。**「殴れるのに殴らない」ではなく「殴る体が
続かない」が真の敗因。**

これとは別に**序盤ベンチ切れ即負けが4-5戦**: 85322665 / 85334490 / 85343306 /
85339627 / (85319428)。T2-6でベンチ0のまま前を取られて終了。最終手札にたねが無く、
盤面補充手段を最優先で切れていなかった。

その他の実確認事項:
- 山札切れ負け: **0件** (v3の山札フロア max(8,サイド+3) は有効。v4でも維持)
- ミスト付き相手へのPowerful Hand 0ダメ攻撃: 2件 (85328678, Kangaskhan戦, 敗北)
- リッチエネのライン貼り: 4件(うち負け試合2件)。{C}しか出せず超要求を満たさない
- 低山札での任意消費: 6件、ただし負け試合0件 (優先度低)
