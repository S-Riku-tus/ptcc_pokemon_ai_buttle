# Grimmsnarl ML v11.1 revision, 2026-08-08

## Scope

This revision changes the existing `grimmsnarl_ml_v11` directory rather than
creating v12. It implements the actionable parts of the ladder autopsy without
treating the noisy final-rating difference as a measured strength regression.

## Agent changes

1. **Restore the missing v9 lineage.** `ranker_model.json` is now byte-identical
   to v9 (`b0397a4a...b91836c`): 1,485 trees, 822 features, unconditioned
   current-top-four consensus. The deck, fallback policy and arithmetic planner
   are unchanged.
2. **Target Alakazam going second at the engagement gate.** The default path
   retains one arithmetic search per turn. When `firstPlayer != yourIndex` and a
   public Abra/Kadabra/Alakazam is in play, the layer may search twice in that
   turn. Candidate cap, rank margins, two determinizations and strict
   non-regressive acceptance are unchanged.
3. **Make the trigger measurable.** Diagnostics now expose
   `alakazam_second_considered` and `alakazam_second_extra_searches`, plus the
   generic and targeted per-turn limits.

This is deliberately an engagement change, not an Alakazam-specific action
heuristic. The available logs identify too few instances to prove that a
particular Stamp, Boss, Munkidori or evolution rule is universally better.

## Measurement repair

`probe_grimmsnarl_v11_ladder_overrides.py` now calls both policies on every
legal recorded selection, including multi-pick and optional zero-pick selects,
and passes those observations through `observe_external`/`Planner.note`.
Multi-pick decisions are retained in reproduction and divergence counts, and
the report includes a `selection_sizes` ledger. The per-game search count also
uses the actual `searched` diagnostic key instead of the nonexistent
`searches` key.

The runtime hooks accept list selections without inventing ranker corpus
history: only a one-element selection can identify a single chosen semantic.
